## 发现的问题与处置

### A. 已修复并重跑（高严重度）

1. **`build_isolate_dataset.py` acc2cid key bug（新发现，最高严重度）**
   - `acc2cid` 只按 accession 建 key，同一 accession 出现在多个亚型 tsv（264 个跨亚型重复）时，后处理亚型覆盖先处理亚型 → **267 行 isolate 继承了错误亚型的 cluster 标签**（H1:150 / H5:110 / H3:7）。
   - 影响（限定 split/embedding 覆盖的 11,060 集合）：`label_is_jump` 错 9 行、`label_is_jump_human` 错 5 行、`iso_interval_days` 错 5 行；jump 标签错误行分布 train 2 / val 1 / test 3 / h5_holdout 3。
   - 修复：key 改 `(subtype, accession)`；重跑 `build_isolate_dataset.py`（11,714 行不变，无掉行）。`build_jump_labels.py` 的 acc2cid 是 per-subtype 的，无此 bug。

2. **clean/aligned 与 split/embedding 不同步（07-12 遗留）**
   - 07-12 重建数据时把 201 条 2026 年 isolate 并入 clean/aligned（11,261 行），而 split/embedding 停在 11,060；且 2026 行在 clean 中位置交错 → 按行位置对齐即静默错位（interval_exp 07-17 结果因此作废，已于 08-02 修复）。
   - 处置：新建 `datascripts/rebuild_isolate_tables.py`，从 all_isolates.csv 重建 clean（去 unknown + 排除 2026）/2026/aligned 四表，**行序重排为 isolate_split.csv 行序**（key 集合断言相等），恢复 clean == split == embedding 逐行一致的原始设计。
   - 决策：2026 不进 split（191 条 H1/H3 会进 train/val/test 造成前瞻泄漏），维持 07-10 原始设计；如需纳入需另议。

3. **`build_aligned_dataset.py` 已损坏**：引用不存在的 `all_aligned.fasta`（现有产物是 `all_aligned_merged.faa`，裸 accession header）。修复为读 merged faa + 裸 accession 查找 + 补 `iso_interval_*` 两列。

4. **防呆**：`extract_embeddings.py` / `extract_embeddings_aligned.py` 加行序断言（DATA_CSV 必须逐行等于 isolate_split.csv），防止重跑生成错位 npy 覆盖有效文件。

### B. 记录在案、未修（影响小或已有替代）

5. **"多 seed 验证"空转**：`binding_exp/train_probe.py` 与 `jump_exp/verify_layers.py` 用 lbfgs + 变 random_state，但 lbfgs 不用 random_state → 5 次结果完全相同（std=0/1e-16），报告的 mean±std 有误导性。且 verify_layers 硬编码 C=1.0 而非 sweep 最优 C，数字与 layer_sweep 对不上；**结论应以 verify_layers_bootstrap 版为准**。
6. `finetune_lora.py` mean-pooling 的 EOS 排除 off-by-one（`mask[:, -1]=0` 对 padding 批中短序列无效，~1/560 token，数值影响极小）。
7. `train_probe_interventions.py` 的 cluster 权重分母含 holdout（轻微偏差，无害）。
8. binding_exp train/test 有 1 对完全重复序列（随机划分未去重，对 AUC 影响可忽略）。
9. jump_exp 的 `train_probe.py` / `train_probe_compare.py` / `verify_h7_auc.py` / `diagnose_h7.py` / `diagnose_direction.py` 按位置取 `data_df["subtype"]`：数据行序恢复后**可正常运行**，但仍属脆弱模式，未来数据更新需小心。
10. 08-01 的 jump_exp 下游分析（layer_sweep / loso_matrix / interventions / unified_arch / verify_* / layer_probing / finetune_lora）用修复前 labels 计算（差异 ≤9/11,060 行），未重跑，结论不可能翻转；如需严格一致可重跑。
11. `data/splits/cluster_split.json` 过时且 cluster_id 跨亚型有歧义 → data/README.md 已标注弃用，统一用 isolate_split.csv。

### C. 文档同步

## 三实验健康度结论

- **binding_exp**：安全，无需重跑。自包含（外部 402 条），embedding/标签/split 逐行一致实测通过；GridSearchCV 只用 train，test 只终评。仅有空转 seed 与 1 对重复序列两个小瑕疵。
- **jump_exp**：现存全部 output JSON 有效（07-12 数据重建前的输出本来就没问题；08-01 的输出由按 split 行序或 accession 对齐的脚本生成）。核心 train_probe 已用修正标签重跑，结论不变。
- **interval_exp**：08-02 重构（共享 loader + 4 类任务 + val 选择/test 单次 + bootstrap CI）后，本次再用修正标签重跑，全部数值为当前最新有效版本。
